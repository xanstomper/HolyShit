# Recon Efficiency — High-Value Quick Checks

When hunting for easy "holy shit" vectors on a hardened target, run these discriminating probes FIRST before burning time on full phase-ordered teardown:

0. **CF-origin leak via DNS TXT (SPF) — highest-leverage first move on Cloudflare-fronted targets.**
   `dig +short <target> TXT @1.1.1.1`. A `v=spf1 ip4:<ip> ~all` entry leaks the true origin IP
   (CF anycast = 104.21.x/172.67.x — anything else is likely origin). Verify by connecting
   directly with `http.client` + unverified TLS context + `Host:`/SNI set to the target; if you
   get real app content (vs CF "One moment, please…") the **entire WAF is bypassed** and you talk
   straight to the backend. See `references/wordpress-cloudflare-origin-bypass.md` for the full WP
   playbook (origin probe, chunking, `_embed` user-enum, maintenance-auth discriminator, soft-404
   discriminator).

1. **CORS arbitrary origin + credentials** — `curl -H "Origin: https://evil.com"` on ANY endpoint. If response contains `access-control-allow-origin: https://evil.com` + `access-control-allow-credentials: true`, this is a **CRITICAL** finding (session hijack via cross-origin requests). Test on login, /me, /data, key regen, SSO — all state-changing endpoints.
2. **Rate limiter bypass patterns** — (a) 10 rapid sequential requests often bypass window limiters that only trigger on HPP/duplicate keys; (b) if 429 returns, wait 2s and retry — many decay instantly; (c) if no decay after cooldown + margin, it's permanent lockout DoS; (d) rate limiter keyed on email = per-account DoS, keyed on IP = bypass via X-Forwarded-For rotation.
3. **FastAPI fingerprint** — `{"detail":"..."}` in 404/405 responses + `/openapi.json` publicly exposed = full API map. Always curl `/openapi.json`, `/docs`, `/redoc` on any JSON API.
4. **Discord OAuth state validation** — state cookie is HS256 JWT with `nonce` claim. Test alg:none attack (forge JWT with `alg:none`, empty sig). If rejected, OAuth is likely secure. Check `redirect_uri` is hardcoded (not attacker-controllable).
5. **postMessage origin check** — `window.opener.postMessage(data, window.location.origin)` is **CORRECT** (targets sender origin). `postMessage(data, "*")` or `postMessage(data, attacker.com)` is the vuln. Don't false-alarm on the correct pattern.
6. **SPA ghost-route sweep** — `curl -s -o /dev/null -w "%{http_code} %{content_type}"` on the endpoint list. Only `application/json` is real; `text/html` = SPA fallback ghost. Kills false positives instantly.
7. **WebSocket 101-handshake false negative** — a CDN-fronted WebSocket that returns `101 Switching Protocols` with NO auth headers is NOT vulnerable. The 101 is the proxy/CFN/Cloudflare passthrough; the origin has not seen any application data. Test by exchanging actual frames with Python `socket+ssl`; if the server sends CLOSE 1008 (Policy Violation) on your first frame, the auth gate works. Full technique + code in `references/websocket-auth-testing.md`.
8. **Code-split chunk discovery** — the main SPA bundle only holds the route table. Page components are lazy-loaded as separate chunks. Discover with `grep -oE '"\./[A-Za-z0-9_-]+\.js"' app.js`, fetch each, and mine for `fetch("...")` calls. On one target this revealed an entire `/api/admin/*` portal invisible in the main bundle.
9. **Public-endpoint PII sweep** — before exhausting time on auth-gated endpoints, sweep the public no-auth surface: `/api/leaderboard/*`, `/api/health`, `/api/models/status`, `/api/catalog`, `/api/version`, `/api/ping`. Public endpoints are where easy HIGH-severity wins live (PII dumps, IP echo, version disclosure).
10. **D1 (Cloudflare SQLite) type-error oracle** — any D1-backed endpoint that doesn't validate input type will return `500 {"detail":"Login error: D1_TYPE_ERROR: Type 'object' not supported for value '[object Object]'"}` when you send a JSON object in a string field (e.g. `email_or_user: {$gt: ''}`). This leaks the DB engine, query layer, and confirms input isn't sanitized at the type layer. Send all variants: `{object}`, `[array]`, `null`, `true`, `{number}`. Rate limiters (5/5min) will lock you out after a few — accept the lockout as a negative finding and document the oracle.
11. **/api/health IP-echo recon** — `/api/health` on Cloudflare Pages routers often returns `{name, version, environment, client_ip, hasDb, hasKv}` unauth. The `client_ip` field is a free SSRF oracle — if you find an internal endpoint that returns different content per source IP, the health endpoint validates your proxy chain. Always log it; even if no direct vuln, it fingerprints the stack.
12. **Bundle-hash diffing for re-engagement** — when re-engaging a baselined target, hash every `<script src=...>` in the index HTML (sha256[:12]) and compare to the baseline JSON's `js_hashes`. Identical hash = stale, skip to fresh probes for decaying findings. New hash + `?v=` query bump = redeploy worth full re-probe.
13. **OAuth/SSO wall protocol — credential-bootstrapping is OUT OF SCOPE**: when pre-auth is exhausted and the wall is OAuth/SSO (Discord, Google, GitHub, etc.), the doctrine says "next decisive test REQUIRES an authenticated session." The agent MUST **ASK the operator for a session token, Bearer, or authorized test account** — do NOT bootstrap credentials on your own initiative, even when technically feasible (disposable email + Playwright signup, SMS verification farms, captcha-solving services, or buying a cheap pre-verified account). The mandate scope gate explicitly forbids "operating with gifted/stolen credentials beyond one read-only privilege check"; auto-provisioning a real account on a third-party service to bypass the wall is account fraud, not pentesting. Use the multi-choice `clarify` tool to offer: (a) operator-supplied token/Bearer, (b) operator-authorized existing test account, (c) operator-authorized bootstrapping with explicit acknowledgment of ToS risk, (d) closeout at the wall with a published report. If the operator declines, document the wall in the ledger, write up the pre-auth findings as the deliverable, and stop cleanly. A HIGH-severity pre-auth PII dump is a publishable result; a pre-auth "wall" is not a failure to find a remote vector.
14. **urllib auto-follows 302 redirects — apparent "endpoint returns 200 huge HTML" is often a redirect chain**: `urllib.request.urlopen` follows 302s silently and `r.url` returns the FINAL URL, not the requested one. When an OAuth-start endpoint appears to return ~70KB of unrelated HTML, the body is the FINAL response after the OAuth provider redirect, not what the target's function returned. Use `requests` with `allow_redirects=False` or capture the `Location` header. The OAuth URL is a recon goldmine: `client_id`, `redirect_uri` (open-redirect if attacker-controllable), `scope`, and `state` generation behavior.
14b. **Auth-mode header split** — multi-tenant SPA bundles carry an auth-mode selector header (`X-Chat-Auth-Mode: account|platform_key`). The error chain enumerates itself: endpoint bare → 400 naming the header → each value names the next required credential. Each branch validates DIFFERENT credentials against DIFFERENT backends — treat each branch as its own auth surface.
15. **Rate-limit brute test for code-exchange endpoints** — for any code/token-exchange endpoint: 15–20 rapid POSTs with garbage codes in a shell loop, collect `-w "%{http_code}"`. All 401/400 with zero 429 = brute surface open (no lockout/captcha). Uniform error strings = no oracle; note code entropy/TTL as the unknown the finding hinges on.
16. **Multi-frontend asset host trap** — SPA stacks often serve the same `assets/` paths from MULTIPLE origins (apex, `www.`, `chat.`, `platform.`). A chunk URL can 404 silently on one host variant while 200ing on another; `curl -o` then writes an empty file and downstream grep reads garbage. ALWAYS fetch chunks with `-w "%{http_code} %{size_download}\n"` and verify size > 0 before parsing. Silent empty downloads are the top source of "no findings in bundle" false negatives.
17. **SupaBomb checklist for Kong-fronted Supabase** — with the mined anon key (itself an HS256 JWT `role:anon`): (a) OFFLINE weak-secret crack of the known sig first — zero requests; (b) forge HS256 with anon-key-as-secret against `/auth/v1/user` AND `/rest/v1/` (PostgREST may use a DIFFERENT key — `PGRST301` = separate trust root); (c) alg:none, jwk-header injection, tamper-keep-sig; (d) sweep service paths on the AUTH host, not the api host. GoTrue checks claims BEFORE signature — a `missing sub claim` 403 means sig verification never even ran.
18. **Socket.io method×namespace existence oracle** — unknown namespace acks `40` then sends `44 "Invalid namespace"` ~1-2s later (listen ≥2s or every namespace looks live); on the RPC-over-HTTP surface (`POST /stream<ns>/rpc/<method>`): unknown method → `unknown rpc`, live method → `Invalid parameters`, dead path → `Cannot POST`. Cross both axes = full server method map unauth.
19. **Test BOTH socket.io protocol versions (EIO=3 and EIO=4)** — servers expose both; the production client often speaks the older one, so synthetic testing on the wrong version tests a surface the real app never touches.
20. **Synthetic sockets use the websocket transport, never polling** — CDN node affinity breaks sequential script-side polling with `Session ID unknown` (each request hits a different backend); one long-lived websocket is immune.
21. **engine.io sid-reuse hijack test** — second websocket against a live session's sid: 101 + answered pings = sid is a bearer credential and the websocket Origin allowlist is client-asserted (header-value comparison, fakeable from non-browser clients). Operator fix: bind socket sessions to the HTTP session cookie server-side.
22. **PTR-reverse every infrastructure IP, then whois every name in the funnel** — PTRs leak more family/vendor domains (panel boxes and vendor mail servers identify themselves); unregistered-but-linked names = registration takeover executable same-day for the price of a domain.
23. **Extract request shapes from the client's schema library, never guess** — bundles ship the shared io-ts/zod chunk (compositions like `_({...})`/`type({...})` + enum literals): that IS the server's validation code, giving every param name, enum, and refinement in one pass. Its naming also betrays the trust model (`amount_coins_requested` = server treats the client figure as advisory).
24. **Vite bundles: mine `__vite__mapDeps`, not the quote-grep** — Vite embeds a manifest array listing EVERY lazy chunk (`assets/Name-Hash.js`); extract it from the main bundle, fetch the shared networking chunks, and trace `from"./X.js"` imports to find where socket/API wiring really lives. Re-export stubs (≤1KB chunks) are dead ends — follow the import graph to the real module. This is the Vite variant of #8.
25. **Grep bundles backtick-aware** — Vite/rolldown compiles ALL strings as template literals, so standard `"/api/..."` quote-greps return empty and you conclude "no API surface" falsely. Extract `` `([^`]{4,150})` `` and filter; on a 1.3MB Vite bundle this flipped a null result into the full endpoint/socket/config map.
26. **Dump the compiled env object** — grep `VITE_[A-Z_]+:` value pairs anchored at `VITE_BASE_URL:`: production builds inline the whole runtime config — flag values, third-party IDs, license keys, and policy flags that should never ship (test-mode payment flags ON in prod, New Relic browser license keys, internal bot names).
27. **Replay the runtime-config bootstrap endpoint unauth** — find the config-fetch call in the bundle (pattern: `metadata?uuid=` with a hardcoded default) and curl it: feature flags, chat-room lists, service domains, and internal ops text (slack/devops references) ride it unauth, and its sibling `POST .../socket-token` mints anonymous socket JWTs by design — decode the payload (TTL/aud/claims) rather than guessing the socket auth model.
28. **Decode the socket-factory, don't brute hosts** — the bundle's socket client factory (hostname-template builders like `https://${trade?'trade':'roulette'}.${hostname}`, `path: o || '/s'`, `transports:['websocket']`) yields host + namespace + engine.io path + transport policy in one read. A 400 `{"code":3,"message":"Bad request"}` on the handshake = a grpc-gateway fronting that host, not a dead endpoint — route the connection through a real socket.io client or the harness browser instead of hand-rolled frames.
29. **Public-profile endpoints leak per-user financials unauth — and boolean flags lie until read at the consumer** — sweep `/profile/{username}/public`-shaped endpoints for deposits/withdrawals/per-game profit plus the 200/404/422 username-enumeration oracle, but BEFORE rating any boolean payload field as privilege-bearing (admin/hidden), read the consumer chunk's logic — the semantics live at the use site, not the payload (a flag read as "is-admin" was "show mod actions").
30. **CF custom-challenge WAF: pace 3-4s and wait out 75s** — Cloudflare "IP or Country challenge blocked" custom pages are WAF STATE, not endpoint state: a ~12-request burst triggers an IP-wide challenge that 403s/429s EVERY endpoint for ~75s. Space probes 3-4s apart on such targets and re-read the SAME endpoint after decay before concluding it is gated.
31. **Wayback CDX = id-format oracle for masked/maskable identifiers** — `web.archive.org/cdx/search/cdx?url=<domain>/*&fl=original` then grep for query-param shapes (`modal=user&user=`, `token=`, `r=`, `stag=`). Archived profile URLs expose the id FORMAT and REAL ids on sites that now mask everything (the live feed masks usernames but ships the same 32-char ids — matching the archived format links feed→profile). The same dump surfaces REMOVED auth methods and old affiliate-tag formats. Zero target traffic — run it before brute-formatting any id oracle.
32. **Auth-plane throttle self-DoS: a retry runner can BE the reason the throttle never clears.** App-level auth throttles are often IP-keyed with long windows where 429'd attempts COUNT against the bucket — a 10-min retry loop keeps it drained forever (a fresh wallet/email identity does NOT bypass it when keyed on IP). Discipline: after a burst go FULLY COLD ~2h, then ONE attempt; if 429 again, hourly. Read `retry-after` from the 429 headers and sleep that + margin. Never leave a fast-cycling runner on a throttled auth plane — when a throttle "never clears", suspect your own retry cadence first.
33. **Mine the client for internal TRUST HEADER names before assuming a geo/region wall is unspoofable** — SSR-to-API forwarding leaks the trust vocabulary in the bundle (`ssr-client-ip`, `country`, `region` header builders at call sites like slots-launch). If the API honors client-supplied geo headers, region blocks (`451 er_sign_up_region_block`-class) are a header away. Grep chunks for `ssr-client-`/`x-client-geo`/`cf-ipcountry` patterns and test the spoof on the LEAST-throttled endpoint that discriminates by region (game launch/demo endpoints), never on the auth plane (see #32).
34. **Sweep known paths with POST+`{}` too — GET-only sweeps miss the POST-shaped API.** An endpoint can be POST-only (`POST /v1/game-history` → 201 with the global feed while every GET on it 404s). One pass: replay every discovered `/v1/*` path with `-X POST -d '{}'`; 404 = method-bound ghost, 200/201/400/500 = a real POST surface. Log the 500s as regressions.
35. **Strict validators report ONE field per request — enumerate the accepted-schema iteratively.** Frameworks that name the failing field (`er_field_validation_<name>`, Pydantic `loc`) reject the FIRST bad field only, so a body of all-wrong-typed guesses reveals just one field. Send one valid-minimal body + ONE wrong-typed guess per request: `er_field_validation_X` = X is a real validated param; silent 201/200 = ignored or loosely (truthy) validated. A ~30-guess pass maps the full filter vocabulary — then re-test the loosely-validated ones with real types (truthy `"x"` often behaves as `true`).
36. **When the operator's goal is a bounty, verify a claim channel BEFORE the deep hunt** — `/.well-known/security.txt` on the apex + mirrors, ToS grep for disclosure/bounty language, and a platform search (Bugcrowd/HackerOne/Intigriti/Immunefi/YesWeHack/Cantina) for the target and its family. No program + silent ToS = no payout channel exists — say so in the first status, not after 20 probes; the deliverable becomes a disclosure package (see `engagement-report-pattern.md`), and the same playbook moves to a scoped program.
